# Phase 4: Multi-Source Verifier

## What I built

The verifier reads `BridgedFMOutput` objects produced by Phase 3
bridges and the LLM's typed `PhysicalStateClaim`, runs five sources,
and emits a structured `VerifierVerdict` with a per-source
breakdown plus a revision `Hint`.

### `fmllm.verifier`

- `schema.py` - `PhysicalStateClaim`, `SourceDecision`,
  `SourceVerdict`, `Hint`, `VerifierVerdict`, and `SourcesConfig`
  with E4 ablation presets V0..V4. All Pydantic with `extra="forbid"`.
- `integrator.py` - `Verifier` class plus `build_default_verifier`
  factory. Aggregates per-source verdicts (any `FAIL` -> `FAIL`;
  any `CAVEAT` -> `CAVEAT`; otherwise `PASS` or `SKIP`). Builds
  per-flagged-source revision suggestions in `Hint`.
- `sources/rule_library.py` - registry of per-constraint check
  functions via `@register_check`. Default checks for the seven
  constraints declared across FM1/FM2/FM3 metadata: `positions_in_box`,
  `non_negativity`, `distribution_normalization`,
  `distribution_non_negativity`, `atom_count_consistency`,
  `permutation_invariance`, `translation_equivariance`,
  `extensive_scaling`, `equipartition`. Each check returns a
  `passed`/`confidence`/`message`/`evidence` dict. Hard checks
  failing produce `FAIL`; soft checks failing produce `CAVEAT`.
- `sources/literature.py` - JSON-backed lookup against
  `data/literature/clusters.json`. Match by atom count and motif,
  compare FM2 energy to the reference within a configurable
  tolerance.
- `sources/cross_fm.py` - reads `dependencies` from each bridged
  output, groups by shared variable, compares pairwise. Uses a
  calibrated `CrossFMToleranceMatrix` when supplied; else
  hard-coded fallback tolerances. Disagreement above the tolerance
  produces `CAVEAT`; above twice the tolerance produces `FAIL`.
- `sources/simulator.py` - short MD rollout from the claim's
  positions and temperature. Compares per-atom mean kinetic energy
  to the claim. `FAIL` only on physical divergence (max radius
  exceeds bound).
- `sources/conformal.py` - reads `source.in_distribution` and
  checks claim membership in `Prediction.uncertainty` (FM2's
  symmetric energy band). Caveat for either trigger; never `FAIL`.

### Literature database (`data/literature/clusters.json`)

Generated by `scripts/build_literature_db.py` from canonical
structures. 12 entries covering N in
{5, 7, 9, 11, 13, 17, 19, 21, 25, 30} crossed with motif in
{triangular_disk, ring} where the (N, motif) pair is valid per
`fmllm.physics.structures.VALID_MOTIFS_FOR_N`. Each record carries:

- `n_atoms`, `motif`,
- `per_atom_potential_energy_lj` (computed analytically under the
  project's LJ Hamiltonian),
- `rdf_first_peak_lj`, `diameter_lj`,
- a `reference` citation string.

Re-run the script after any change to the structure generators or
the LJ Hamiltonian; the JSON is deterministic.

### E4 ablation enablement

`Verifier.verify` accepts a runtime `sources_config` parameter that
overrides the default. `SourcesConfig.for_ablation(level)` returns
the addendum's V0..V4 presets:

- V0: nothing active.
- V1: rules only.
- V2: rules + conformal.
- V3: rules + conformal + cross-FM.
- V4: all five sources.

Disabled sources contribute a `SKIP` verdict so the trace stays
shape-consistent across conditions. This is the architectural slot
the E4 experiment script (Phase 8) plugs into.

### Tests (`tests/test_verifier.py`, 24 tests)

- Schema: presets V0..V4 expose the right active-source lists; an
  unknown level rejects.
- Rule library: clean inputs pass; non-negativity violation FAILs;
  position outside the box FAILs; count head / objectness mismatch
  FAILs.
- Cross-FM: skips when no shared variable; passes when claim
  matches FM1's count; CAVEATs when claim disagrees; respects a
  supplied tolerance matrix.
- Conformal: passes when in-distribution and claim in band;
  CAVEATs when claim outside band; CAVEATs when FM marks itself OOD.
- Simulator: skips without positions; passes on a consistent claim
  (HCP-7 cluster at low T).
- Literature: passes for an FM2 prediction near the reference;
  CAVEATs on strong disagreement; skips when no atom count is
  available.
- Integrator: V4 runs every source; V0 produces all SKIPs; V1 runs
  only rules; FAIL aggregates over CAVEAT; hint lists the flagged
  sources; verdict JSON round-trips.

All 142 local tests pass in 1.1 seconds.

## What the user runs to verify Phase 4

### Local laptop (no GPU)

```
git pull
uv sync --extra dev
uv run pytest -m "not gpu" -v
```

Expect 142 passing tests (118 from before + 24 new verifier tests).

### Remote 4xH100 host

The verifier is CPU-only Python; no remote-only verification step
beyond running the same pytest invocation against the live
environment. A practical end-to-end smoke test (load FMs, run
forward passes, bridge outputs, verify against a synthetic claim)
arrives in Phase 5 alongside the orchestrator.

If you want a Phase 4-only smoke now, regenerate the literature DB
to confirm everything composes cleanly:

```
uv run python scripts/build_literature_db.py
```

That produces 12 entries and writes them to
`data/literature/clusters.json`.

## Known caveats

- **Simulator source uses NVE.** It does not thermostat the
  trajectory it runs from the claim. For long n_steps the per-atom
  mean KE drifts slightly from the initialization temperature. The
  default `n_steps=100, dt=0.005` keeps drift small (well inside
  the default 20% relative tolerance).
- **Literature DB has only canonical motifs.** When a claim names
  a motif outside `{triangular_disk, ring}`, the source falls back
  to the lowest-energy reference at the matching atom count, which
  is the right floor for energy comparisons but loses motif-aware
  matching.
- **Cross-FM tolerance fallbacks are coarse.** Without a calibrated
  matrix, the source uses hard-coded defaults
  (`atom_count: 1.0`, `temperature: 0.20`,
  `per_atom_potential_energy: 0.10`). Phase 8's E4 should ship a
  calibrated matrix produced by
  `fmllm.fms._calibration.cross_fm_tolerance` once the FM
  predictions have been collected on the calibration set.
- **Position-set checks are limited to FM1's payload.** The rule
  library does not currently verify that LLM-claimed positions
  agree with FM1's. Add as a registered check in Phase 5 once the
  orchestrator's claim shape settles.
